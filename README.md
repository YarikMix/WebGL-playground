# WebGL-playground

Прототип главной страницы сервиса блокнотов (аналог Google Colab) в космической
стилистике. Репозиторий нужен, чтобы сравнить реализации анимированного фона —
планеты и звёздного неба.

| Ветка | Фон | Демо |
|---|---|---|
| `main` | Canvas 2D + CSS-диск планеты, без библиотек | <https://yarikmix.github.io/WebGL-playground/> |
| `webgl` | чистый WebGL, планета одним фрагментным шейдером, без библиотек | <https://yarikmix.github.io/WebGL-playground/webgl/> |
| `r3f` | официальный React + three.js через react-three-fiber и drei | <https://yarikmix.github.io/WebGL-playground/r3f/> |

`main` и `webgl` отличаются по сути одним файлом: `git diff main webgl -- sky.js`.
Ветка `r3f` — отдельное приложение на Vite со своей структурой.

## Эта ветка: React 19 + TypeScript + react-three-fiber + drei

```bash
bun install
bun run dev         # разработка
bun run typecheck   # tsc --noEmit, strict
bun run build       # проверка типов + сборка в dist/
```

React закреплён на 19.2: `@react-three/fiber` 9.7 объявляет `react >=19 <19.3`.
TypeScript 7, `strict` плюс `noUncheckedIndexedAccess`; сборка падает на ошибке типов.

### Ленивая загрузка сцены

three.js, R3F и drei для первого экрана не нужны, поэтому сцена вынесена в отдельный чанк
(`React.lazy`), а `import()` стартует сразу, параллельно с первым рендером:

| Чанк | Размер | gzip |
|---|---|---|
| основной (React + интерфейс) | 206 КБ | 66 КБ |
| `Sky` (three.js + R3F + drei + сцена) | 979 КБ | 265 КБ |

Пока чанк грузится, фон — чистый CSS: тот же диск `.limb` и свечение, что в ветке `main`.
Переключение идёт в два шага, и оба — только после реально отрисованного кадра (`FirstFrame`):

1. `skyReady` — `.page` получает класс `.webgl`: канвас проявляется, CSS-фон гаснет (crossfade 0,7 с);
2. `glassReady` — DOM-карточки становятся прозрачными. Раньше нельзя: пока шейдер стекла
   компилируется, под прозрачной карточкой не было бы ничего.

Канвас до готовности скрыт через `opacity`, а не `display: none`: с нулевым размером R3F не рисует
кадры, и сигнал готовности не пришёл бы никогда. Если чанк не загрузился или WebGL недоступен,
`SceneBoundary` гасит ошибку — страница остаётся на CSS-фоне с обычными карточками.

Замер на эмуляции Slow 4G: интерфейс виден на 1,6 с, сцена включается на 4,0 с. До разделения
интерфейс ждал бы загрузки всего бандла.

### Как устроена сцена

Сцена живёт в координатах страницы: камера ортографическая (`OrthographicCamera` из drei),
1 единица three.js = 1 CSS-пиксель, левый верхний угол канваса — `(0, 0)`. Поэтому меши
встают ровно на места DOM-элементов: планета — туда, где лежит скрытый CSS-диск `.limb`,
стеклянные плиты — под карточки. Канвас прокручивается вместе со страницей, геометрия
пересчитывается только при изменении раскладки.

Что изменилось по сравнению с веткой `webgl`:

- **Планета стала геометрией.** Там сфера была аналитической (нормаль из координат пикселя),
  а вращение подделывалось поворотом координат шума. Здесь это меш, который вращается через
  `rotateOnWorldAxis`, а шум берётся по направлению в координатах объекта и едет вместе с ним.
  Сам шейдер поверхности (облака, терминатор, огни, атмосфера) перенесён почти без изменений.
- **Liquid glass без своего шейдера.** Плита — `ExtrudeGeometry` с фаской, материал —
  `MeshTransmissionMaterial`: преломление по настоящим нормалям, хроматическая аберрация,
  шероховатость. Блики — `Environment` из нескольких `Lightformer` (без HDR-файлов) и точечный
  свет, который ходит за курсором. `transmissionSampler` включает общий буфер преломления
  three.js: сцена за стёклами рендерится один раз на кадр, а не по разу на каждую плиту.
  Ограничения в 16 карточек, как в ветке `webgl`, здесь нет.
- **Рендер по требованию.** `frameloop="demand"` и собственный тикер на 30 кадров/с;
  пауза, когда канвас вне экрана; при выключенной анимации кадр рисуется только по изменению
  раскладки или движению курсора.

Четыре вещи, которые пришлось учесть:

0. **R3F копирует `uniforms`.** При создании `<shaderMaterial>` обёртки копируются
   (`{ ...uniform }`), поэтому запись в исходный объект — `uniforms.uTime.value = t` — до
   материала не доходит. Векторы при этом «работают» (в копии ссылка на тот же `Vector2`), а
   числа молча застревают на значениях первого рендера: время не шло, а после resize ореол
   атмосферы считал радиус планеты прежним и заливал небо белым. Значения пишутся только через
   ref на материал: `material.current.uniforms.uTime.value = t`.

1. `MeshTransmissionMaterial` считает направление взгляда как `normalize(cameraPosition − pos)`,
   то есть рассчитан на перспективную камеру. С ортографической камерой вблизи преломление
   перекашивает к краям экрана. Камера отодвинута на 100 000 единиц: на проекцию это не влияет,
   а лучи становятся почти параллельными.
2. Камера смотрит строго вдоль Z, поэтому верхняя фаска отражает только то, что лежит в плоскости
   `X = 0`, боковая — в плоскости `Y = 0`. Световые панели окружения стоят по осям; поставленные
   «по диагонали» дают блик только в углу плиты.
3. У `RoundedBox` из drei ширина фаски жёстко равна радиусу скругления. При радиусе 18px плита
   выглядит толстой рамой, поэтому геометрия собрана вручную: скругление 18px, фаска 8px.

### Цена

| | `webgl` | `r3f` |
|---|---|---|
| JS для страницы | 33 КБ исходников (`sky.js` 25 + `app.js` 8), без сборки | 1185 КБ, 331 КБ gzip; до первого экрана — 66 КБ gzip |
| Зависимости | нет | react, react-dom, three, @react-three/fiber, @react-three/drei |
| Liquid glass | свой шейдер, ~70 строк GLSL, до 16 карточек | готовый материал, ~10 строк JSX, без лимита |
| Производительность шейдера планеты | одинаковая: тот же GLSL на том же GPU | |

React и three.js не ускоряют фон: узкое место — фрагментный шейдер планеты, он один и тот же.
Выигрыш — в скорости разработки: настоящая 3D-сцена, готовые материалы и свет, декларативная
связь сцены с состоянием интерфейса.

## Экран входа

Пока нет сессии (`localStorage['nebulab-session']`), вместо списка блокнотов показывается
форма входа/регистрации — одна карточка с двумя состояниями. Переключение между ними
(«Войти» ↔ «Создать аккаунт») не меняет DOM-узлы: свет сцены сам проезжает по карточке,
как терминатор — граница дня и ночи — идёт по диску планеты. Технически это разворот
направления на солнце (`SUN_DAWN`, `SWEEP_ANGLE`) в плоскости экрана на время CSS-перехода
формы; обе анимации делят одну длительность — константу `SWEEP_MS` из `src/scene-config.ts`,
чтобы свет и вёрстка не расходились по времени.

Почему свет, а не залитая цветом панель: экран входа — первое, что видит человек, и он же
показывает главный приём сцены (терминатор, жидкое стекло карточек) ещё до того, как есть что
листать. Плоская цветная панель этого не даёт и вводит второй визуальный язык рядом с тем,
что уже есть на экране блокнотов. Обоснование и раскладка по кадрам — в спеке:
[`docs/superpowers/specs/2026-09-21-auth-terminator-design.md`](docs/superpowers/specs/2026-09-21-auth-terminator-design.md).

Форма не зависит от сцены: `AuthCard` рендерится независимо от `<Sky>`, поэтому она полностью
рабочая (валидация, вход, переключение режима) и до того, как догрузится ленивый чанк сцены,
и если WebGL недоступен вовсе — тогда `SceneBoundary` гасит сцену, и под карточкой остаётся
статичный CSS-фон (тот же диск `.limb`, что в ветке `main`). На ширине до 860px карточка
становится одноколоночной: форма и приглашение («Уже есть аккаунт?» / «Ещё нет аккаунта?»)
идут одно под другим, приглашение — в одну строку. При `prefers-reduced-motion: reduce`
CSS-переход и разгон тикера сцены отключены — режим меняется сразу, без проезда.

На крупной плите карточки входа (в разы больше карточек блокнота) материал стекла настроен
мягче: выше `roughness` и ниже `chromaticAberration`/`anisotropicBlur` у `MeshTransmissionMaterial`
в `GlassCards.tsx` — точечный блик от курсора превращается в широкое мягкое пятно вместо яркой
точки, которая иначе стояла бы прямо на тексте или полях формы.

## Деплой

`.github/workflows/pages.yml` на каждый push в `main`, `webgl` или `r3f` собирает сайт из трёх
веток (эту — через `bun run build`) и публикует в GitHub Pages. Файл workflow должен совпадать
во всех ветках: push запускает его из той ветки, в которую пришёл.
