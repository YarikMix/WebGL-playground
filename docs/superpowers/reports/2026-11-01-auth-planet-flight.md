# Проверка auth-перелёта — 2026-11-01

Реализованы две неподвижные 3D-планеты, близкая траектория B, DOM-формы с сохранением ввода и доступный переключатель соседней планеты. Список/редактор используют прежнюю ортографическую композицию в том же Canvas. Зависимости и lockfile не менялись.

## Проверки поведения

- `bun test`: 64 pass, 0 fail; новые 6 тестов модели перелёта сначала упали из-за отсутствующего модуля, затем прошли. Проверяют направление, easing, длительность, повторные запросы, устаревшее завершение и большой перерыв между кадрами.
- `bun run build`: typecheck и production build проходят. Vite предупреждает о размере Sky-чанка >500 КБ; динамическое разделение сцены сохранено.
- Браузер через Chrome DevTools Protocol, настоящие DOM/React/WebGL без mock-компонентов: login → signup → login; пять быстрых кликов; клавиатурный Enter; inert/снятие фокуса в полёте и фокус логина после проявления; один Canvas; сохранение логина/пароля; сброс ошибок и видимости пароля; `taken`; блокировка mode-switch во время 600-мс submit.
- 375×812, 390×844, 375×500, 1280×1024 и 1440×900; оба режима и resize посреди пути. Область соседней планеты не пересекает форму, не выходит за viewport, не меньше 44×44 CSS px; подпись помещается по ширине. При малой высоте страница прокручивается. Скриншоты сверены визуально.
- Потеря WebGL в полёте переводит в целевой режим на статичном оформлении; повторное переключение работает сразу. При полном отсутствии WebGL Canvas не запускается, формы работают, uncaught rejection отсутствует.
- Задержка JS-модуля Sky: форму можно переключить до готовности; поздняя сцена принимает текущий режим. Блокировка модуля: формы доступны, ранний preload rejection обработан, ошибка сообщается error boundary.
- Reduced-motion: мгновенная смена режима и камеры; счётчик render.frame не растёт в покое. Заморозка страницы через CDP на >1,8 с: после активации камера прибывает без повторного полного полёта.
- Signup → список → редактор → список → logout; вход по защищённой ссылке на блокнот и history.back. Рабочая сессия/redirect сохранены; камера списка ортографическая.

## Производительность

Production preview Vite, Chrome 154, WSL2/X11, Intel Core i5-13600KF, RTX 4070 Ti через аппаратный ANGLE/D3D12; 1440×900, DPR 1, без CPU throttling. После прогрева: 10 секунд покоя, 10 перелётов с паузами около 350 мс, затем 2 секунды покоя.

| Период | Частота WebGL-отрисовок | Медиана интервала | P95 интервала | Long tasks >50 мс |
|---|---:|---:|---:|---:|
| Покой, 10 с | 29,98/с | 33,4 мс | 34,0 мс | 0 |
| 10 перелётов с короткими паузами | 56,62/с | 16,7 мс | 33,1 мс | 0 |
| Покой после серии, 2 с | 29,97/с | 33,3 мс | 34,1 мс | — |

Частота серии включает паузы с 30 кадрами/с; P95 тоже учитывает их. Это инструментированный счётчик WebGL clear за JS-задачу, с объединением нескольких проходов одного рендера. Он измеряет вызовы отрисовки, а не доставку кадров на экран или аппаратное GPU-время. Во время отдельного активного участка проверка renderer.info дала 85 render-вызовов на 79 browser rAF; счётчик render включает вспомогательные проходы.

Первый замер обнаружил около 30 отрисовок/с и в полёте: внешний rAF-тикер каждый раз заново запускал demand-цикл R3F. Регрессионная браузерная проверка упала (46 render-вызовов на 79 rAF); запрос следующего кадра из активного `useFrame` исправил это, не переводя покой в постоянный render loop.

В production до и после 10 перелётов: **37 живых WebGL-буферов, 5 текстур**. Дополнительная проверка `renderer.info.memory` в dev после 10 перелётов записана в [resources.json](assets/auth-planet-flight/resources.json); 10 геометрий / 1 текстура до и после, Canvas один (нативный счётчик выше включает служебные WebGL-текстуры). ## Решения при реализации

1. Нативный worktree-инструмент не нашёл Git в родительском cwd; использован `git worktree` в репозитории с игнорируемым `.worktrees/`. Цена: одна запись в `.gitignore`.
2. Длительность проверяется через поведение модели и формы, без дублирующих тестов констант. Цена: проверка fade остаётся браузерной.
3. Для узких/высоких окон выбран симметричный близкий ракурс и вычисляемый FOV вместо фиксированных 82°: иначе соседняя планета обрезалась. Цена: перспектива отличается от широкого экрана.
4. Перед Canvas один раз проверяется WebGL2; временный контекст сразу освобождается. Причина: асинхронный configure R3F обходит обычный boundary при отсутствии контекста. Цена: создание одного временного контекста на запуск сцены.
5. В активном `useFrame` запрашивается следующий demand-кадр для частоты дисплея. Цена: возможен один дополнительный кадр на завершении.

## Ограничения

Физический телефон не подключён: мобильный GPU/FPS, Safari/iOS, экранная клавиатура настоящего устройства, батарея и нагрев не измерялись. Узкие размеры — эмуляция viewport на настольной RTX, не доказательство производительности смартфона. Результат относится к этой MVP-сцене и указанной машине; сравнение с прежним CSS-бенчмарком не определяет стоимость нового 3D-интерфейса.
