# Экран блокнота, маршруты и вход по логину

Дата: 2026-09-27. Ветка реализации: `feat/notebook-editor` от `r3f`. Статус: согласовано на брейншторме.

## 1. Контекст и цель

Прототип сервиса блокнотов (аналог Google Colab) в ветке `r3f` уже умеет два экрана: вход/регистрацию
и список блокнотов. По продуктовым требованиям модуля 1 не хватает третьего — **страницы файла**:
открытый блокнот, в котором можно создавать и удалять ячейки.

Требования модуля 1 (со скриншотов Colab):

- ячейки двух типов — код и текст;
- создание ячеек двумя способами, **оба** обязательны: кнопки «+ Код / + Текст» в панели сверху
  и такие же кнопки на стыке ячеек;
- удаление ячеек;
- поля ячеек **только для чтения**: редактор кода встраивается во втором модуле;
- содержимого у ячеек нет — только плейсхолдеры. Код на карточках списка — такая же заглушка.

Вместе с экраном меняется каркас: появляются настоящие адреса, корень сайта начинает открывать
приложение из `r3f`, вход переходит с почты на логин, из подвала уходят переключатели вариантов.

## 2. Решения брейншторма

| Вопрос | Решение |
|---|---|
| Панель ячейки (↑ ↓ ✎ 🗑 ⋯ у Colab) | Только удаление. Остальных кнопок нет вовсе, даже неактивных |
| Фон экрана блокнота | «Тихий космос»: цвет `--void` и звёзды, без планеты и без liquid glass; ячейки — CSS-стекло |
| Содержимое при открытии | Чередование «текст → код → …» с плейсхолдерами, число ячеек — как на карточке |
| Что переживает перезагрузку | Только адрес. Ячейки живут в памяти |
| Роутер | TanStack Router, маршруты кодом, хеш-история |
| Вход | Становится маршрутом `#/login`; поле «Почта» → «Логин» |
| Регистрация | Логин + пароль + повтор пароля, имени нет |
| Деплой | `r3f` → корень сайта, `main` → `/canvas/`, `webgl` → `/webgl/`, `/r3f/` → редирект на корень |
| Подвал | Без переключателей: всегда liquid glass, анимация включена |
| Тесты | Юнит-тесты `bun test` на чистую логику + ручная приёмка по чек-листу (§9) |

## 3. Маршруты

### 3.1 Таблица

| Адрес | Экран | Без сессии | С сессией |
|---|---|---|---|
| `…/WebGL-playground/` = `#/` | список блокнотов | → `#/login?redirect=/` | список |
| `#/login` | вход и регистрация | форма | → `redirect` или `#/` |
| `#/notebook/$id` | блокнот | → `#/login?redirect=/notebook/$id` | блокнот |

Сценарии, которые из этого следуют:

- впервые открыли корень сайта — видна форма входа;
- «Войти» → адрес меняется с `#/login` на `#/`, открывается список;
- клик по карточке → `#/notebook/3`;
- ссылка на блокнот без входа → форма → после входа тот же блокнот;
- выход через аватар → `#/login` (и `mode` сбрасывается на `login`, как сейчас);
- логотип `cellestial` над карточкой входа — ссылка на `#/`: с сессией это список, без сессии снова форма.

### 3.2 Почему хеш

GitHub Pages не отдаёт `index.html` на произвольный путь. Красивые пути (`/WebGL-playground/login`)
возможны только через трюк с `404.html`, при котором каждая прямая ссылка сначала отвечает статусом
404. Для прототипа хеш честнее: `createHashHistory()` из `@tanstack/react-router`.

### 3.3 Устройство

Маршруты задаются кодом (`createRootRoute` / `createRoute`) в `src/router.tsx`, без файлового
роутинга и Vite-плагина — кодогенерация на три маршрута не окупается.

- **`$id`** разбирается в `params.parse`: строка из цифр → положительное целое, иначе ошибка
  разбора. Неразобранный id и id, которого нет среди блокнотов, ведут `redirect` на `/` с тостом
  «Блокнот не найден». Так же ведёт себя блокнот, созданный до перезагрузки: после неё его нет.
- **`redirect`** у `/login` — search-параметр, проверяется в `validateSearch`: принимается только
  строка, начинающаяся с `/`, всё остальное отбрасывается (защита от открытого редиректа наружу).
- **Охрана по сессии** — в `beforeLoad` маршрутов. Сессия попадает в них через контекст роутера
  (`createRootRouteWithContext<{ session: Session | null }>()`), корень обновляет его и вызывает
  `router.invalidate()` при входе и выходе.

Навигация внутри приложения — только `<Link>` и `navigate()`; `href="#"` уходят.

## 4. Каркас приложения

### 4.1 Корень держит общее

`App.tsx` становится компонентом корневого маршрута и держит всё, что должно пережить смену экрана:

- сессию и `mode` формы входа (от него зависит свет сцены — как сейчас);
- массив блокнотов — **поднят из `Notebooks.tsx`**. Иначе при уходе в блокнот и возврате список
  размонтируется, и только что созданный «Без названия» пропадёт;
- тост — **поднят** из экранов: «Блокнот не найден» показывается в момент редиректа, когда экрана
  блокнота уже нет;
- `<Sky>` — одна на все экраны, шейдеры не компилируются заново при переходах;
- вместо выбора `isAuth ? <Auth> : <Notebooks>` рендерится `<Outlet />`.

### 4.2 Контекст вместо пропсов

У маршрутных компонентов нет пропсов, поэтому корень отдаёт экранам общее через React-контекст
`ShellContext` (`src/shell.ts`): рефы сцены (`glowRef`, `limbRef`, `cardsRef`), `glassOn`,
`reducedMotion`, сессию, `mode`/`setMode`, блокноты и операции над ними, `toast(text)`, `signIn`,
`signOut`. Хук `useShell()` бросает понятную ошибку, если вызван вне корня.

### 4.3 Какой экран что сообщает сцене

| Экран | `planet` | стекло | `spin` |
|---|---|---|---|
| `/login` | да | карточка входа | ±`SWEEP_ANGLE/2` по `mode` |
| `/` | да | карточки блокнотов | 0 |
| `/notebook/$id` | **нет** | нет | 0 |

Корень определяет экран по текущему совпадению маршрута (`useMatchRoute` / `useRouterState`).

## 5. Вход и регистрация

### 5.1 Поля

| Вход | Создание аккаунта |
|---|---|
| Логин | Логин |
| Пароль (с показом) | Пароль (с показом) |
| | Повторите пароль |

- В регистрации по-прежнему три поля, поэтому фиксированная высота карточки (коммит 1925157)
  не меняется.
- Показ пароля — один переключатель на поле «Пароль», раскрывает **оба** поля пароля: так их можно
  сверить глазами.
- Логин: `autocomplete="username"`, `autocapitalize="none"`, `spellcheck="false"` — иначе телефон
  поднимет первую букву, и логин не пройдёт правило. Пароли: `current-password` на входе,
  `new-password` на обоих полях регистрации.
- Остальное из спеки входа (§4.5 от 2026-09-21: `aria-describedby`, `role="alert"`, фокус на первое
  проблемное поле, состояние отправки ~600 мс) сохраняется.

### 5.2 Валидация

Момент прежний: на отправку и на уход из поля. Правило логина: `^[a-z0-9_.-]{3,32}$`.

| Ситуация | Сообщение |
|---|---|
| Пустой логин | Введите логин |
| Логин не подходит под правило | От 3 до 32 символов: a–z, 0–9, _ . - |
| Пустой пароль | Введите пароль |
| Пароль короче 8 символов | Нужно не меньше 8 символов |
| Повтор пустой (регистрация) | Повторите пароль |
| Повтор не совпадает (регистрация) | Пароли не совпадают |
| Логин `taken` при регистрации | Этот логин уже занят. Войдите или выберите другой |

Заглавные буквы **не приводятся** к нижнему регистру молча — срабатывает ошибка правила. Молча
менять то, что человек ввёл в поле, которым он потом будет входить, хуже, чем сказать об этом.
Пробелы по краям логина обрезаются перед проверкой (как сейчас у почты).

`validate(mode, values)` экспортируется из `useAuthForm.ts` — её покрывают тесты (§9.1).

### 5.3 Сессия

- `Session` — `{ login: string }` вместо `{ email, name? }`; ключ `cellestial-session` прежний.
- `loadSession` принимает только объект с непустой строкой `login`. Старая сессия с `email` не
  проходит проверку — человек один раз увидит форму входа.
- `initials(session)` — первая буква логина заглавной (как «Я» у Colab).

### 5.4 После входа

`signIn` сохраняет сессию, обновляет контекст роутера и переходит на `redirect` из адреса, а если
его нет — на `/`.

## 6. Экран блокнота

### 6.1 Раскладка

```
┌ шапка (sticky, то же стекло, что у списка) ─────────────────────────────┐
│ ← [лого] Fine-tune ruBERT на отзывах                              [Я]   │
│          21 ячейка · A100 · ● Работает 38 мин                           │
│ ─────────────────────────────────────────────────────────────────────── │
│ [+ Код] [+ Текст]                                                       │
└─────────────────────────────────────────────────────────────────────────┘
      · звёзды ·                  ·                        ·
  ┌ текст ─────────────────────────────────────────────────────── [🗑] ┐  ← выбранная
  │  Заголовок или описание — Markdown                                 │
  └────────────────────────────────────────────────────────────────────┘
                     ( + Код )  ( + Текст )      ← на стыке: при наведении/фокусе
  ┌ код ───────────────────────────────────────────────────────────────┐
  │ [ ] ▶  # Код на Python                                             │
  └────────────────────────────────────────────────────────────────────┘
                     ( + Код )  ( + Текст )      ← после последней: видна всегда
```

**Шапка.** Стрелка «назад» и логотип — ссылки на `/`. Название блокнота (`h1`) и мета той же
формы, что на карточке: число ячеек (живое, со склонением через `plural`), ускоритель, статус
рантайма, «от …» для чужих. Аватар — выход, как на списке. Меню «Файл / Изменить / Вид…»,
«Выполнить все» и «Подключиться» из Colab **не переносятся**: пункты без действий — шум.

**Колонка ячеек** — ширина `.wrap` (1120px).

### 6.2 Ячейка

Общее: заливка `--glass`, градиентный бордер и скругление 18px — как у карточек блокнотов.

- **Код.** Слева счётчик выполнения `[ ]` моноширинным и кнопка ▶ (`aria-label="Выполнить ячейку"`).
  Клик по ▶ — тост «В прототипе выполнение не подключено». Поле — `<textarea readOnly>` шрифтом
  `--mono`, плейсхолдер `# Код на Python`.
- **Текст.** `<textarea readOnly>` шрифтом `--body`, плейсхолдер «Заголовок или описание — Markdown».

Поле — настоящий `textarea`, а не `div`: во втором модуле на его место встанет редактор, разметка
ячейки вокруг не меняется. У каждого поля `aria-label` («Ячейка кода 3», «Текстовая ячейка 4»).

### 6.3 Выбор и удаление

- Клик по ячейке или фокус внутри неё делает её **выбранной**: рамка `--violet` и в правом верхнем
  углу панель с единственной кнопкой «Удалить ячейку» (иконка корзины, `aria-label`).
- Выбранная ячейка одна; она хранится в состоянии экрана по `id`.
- Удаление мгновенное, без подтверждения и без «Вернуть»: в ячейках только плейсхолдеры.
  После удаления выбор переходит на следующую ячейку, а если её нет — на предыдущую; фокус — на неё
  (иначе он падает на `body`).

### 6.4 Добавление

1. **«+ Код / + Текст» в шапке** вставляют ячейку **после выбранной**, а если ничего не выбрано —
   в конец.
2. **Полоса «+ Код / + Текст» на стыке** вставляет ячейку ровно в эту позицию.
   - Между ячейками (и перед первой) полоса проявляется при наведении на промежуток и при
     `:focus-within` — с клавиатуры кнопки доступны по Tab.
   - **После последней ячейки полоса видна всегда.**
   - На тач-устройствах (`@media (hover: none)`) промежуточные полосы показываются только под
     выбранной ячейкой; полоса в конце видна всегда.

Новая ячейка становится выбранной, получает фокус и прокручивается в зону видимости
(`scrollIntoView({ block: 'nearest' })`; при `prefers-reduced-motion` — без плавности).

### 6.5 Содержимое

- Существующий блокнот открывается с числом ячеек, как на его карточке (21 → 21), чередуя
  «текст, код, текст, …», начиная с текста.
- «Новый блокнот» на списке создаёт запись с **одной ячейкой кода** и сразу открывает её
  (`navigate` на `/notebook/$id`), как `Untitled.ipynb` в Colab.
- Любая вставка или удаление ставит блокноту `edited: 'только что'` — после возврата на список
  карточка показывает актуальное число ячеек и время.
- Всё живёт в памяти корня; перезагрузка возвращает стартовое состояние.

### 6.6 Пусто

Если удалить все ячейки — блок в стиле `.empty` списка: «В блокноте пусто», подпись «Добавьте
первую ячейку» и две кнопки «+ Код / + Текст». Полосы в конце в этом состоянии нет — её роль
выполняет этот блок.

## 7. Сцена

### 7.1 Проп `planet`

`Sky` получает `planet: boolean`. При `false`:

- не рендерятся `Planet` и `Backdrop` (ореол атмосферы и свечение за заголовком привязаны к планете
  и hero; цвет космоса и так даёт `<color attach="background">`);
- `GlassCards` не рендерится;
- `Stars` и `Meteor` остаются. Сейчас они берут `planet` для отсечения звёзд диском и остановки
  метеора у кромки — при `planet === null` отсечения нет.

Переход между экранами без анимации: экран меняется целиком, а канвас тот же — звёзды не мигают.

### 7.2 `SceneLayout` и `useSceneLayout`

- `SceneLayout.planet: PlanetGeometry | null`, `SceneLayout.glow` — тоже `| null`.
- `useSceneLayout` больше не выходит молча, когда нет `.limb` или элемента свечения: на экране
  блокнота он отдаёт раскладку с `planet: null`, `glow: null`, `cards: []` и высотой `BASE_HEIGHT`
  (звёзды растворяются в `--void` на том же расстоянии, что и на списке).
- Сейчас эффект хука зависит только от `glass` и ловит смену экрана косвенно, через `ResizeObserver`
  страницы. Добавляется явная зависимость — ключ текущего экрана: при смене экрана наблюдатели
  переподписываются на новые элементы.

### 7.3 Всегда liquid glass, анимация включена

- `cards` и `motion` перестают быть состоянием: `wantGlass = true`, `motion = !reducedMotion`.
  `prefers-reduced-motion` — требование доступности, а не опция, и продолжает гасить движение.
- `loadSetting`/`saveSetting` и ключи `sky-cards-r3f`, `sky-motion` больше не используются —
  функции удаляются из `data.ts`, если больше нигде не нужны. `CardsMode` уходит из `types.ts`.
- Двухступенчатая готовность (`skyReady` → `glassReady`) и CSS-фолбэк не меняются.

### 8.1 Раскладка сайта

| Адрес | Источник |

| `/WebGL-playground/canvas/` | ветка `main` как есть (Canvas 2D) |

Правки в `main` и `webgl` (workflow + подвал) идут отдельными ветками и PR в эти ветки.
Порядок слияния: сначала PR в `r3f`, затем в `main` и `webgl`. До слияния последних сайт уже
собирается по новой раскладке (workflow из `r3f`), а в подвалах архивных вариантов временно

## 9. Проверка

### 9.1 Юнит-тесты (`bun test`)

Раннер встроен в Bun, зависимостей не добавляется; в `package.json` — скрипт `"test": "bun test"`.
Покрывается то, где ошибка тихая:

- `notebook-cells.ts`: стартовое чередование по числу; вставка в начало, середину, конец и после
  выбранной; удаление первой, средней, последней и единственной ячейки; уникальность id;
- `validate` из `useAuthForm.ts`: все строки таблицы §5.2, в том числе заглавные буквы, 2 и 33
  символа, недопустимый символ, пробелы по краям;
- `loadSession`: корректная сессия, старая с `email`, битый JSON, пустой логин;
- разбор `$id` и `redirect`: `"3"` → 3; `"abc"`, `"-1"`, `"0"`, `"3.5"` → ошибка;
  `"https://evil"` и `"//evil"` в `redirect` отбрасываются.

### 9.2 Ручная приёмка

Проходится в браузере на `bun run dev`, со скриншотами:

1. Корень без сессии → `#/login`. Вход → `#/`. Выход → `#/login`, форма в режиме входа.
2. `#/notebook/3` без сессии → форма → после входа блокнот 3.
3. `#/notebook/999` и `#/notebook/abc` → список и тост «Блокнот не найден».
4. Карточка → блокнот с тем же числом ячеек, чередование с текста → удалить 2, добавить 1 →
   «назад» в браузере → на карточке верное число и «изменён только что».
5. «+ Код / + Текст» в шапке: после выбранной; без выбора — в конец. На стыке — ровно туда.
   Полоса после последней ячейки видна без наведения. Удалить всё → пустое состояние → добавить.
